# Skills Auditor 0.10.0

Skills Auditor can now plan, apply and verify a fixed Skill collection across
multiple workspaces and existing local or SSH environments. Workspace declarations
combine a common baseline with explicit project replacements or exclusions.
Environment, workspace, Agent host and installation identities remain separate;
Potology is an optional route adapter rather than a core dependency.

Sources support full pinned Git commits and explicitly marked local snapshots.
Packages retain selected relative entrypoints, scripts, templates and declared
outer dependencies. An optional source-owner environment captures content where
it is authored; controller paths are not substituted for remote paths. Plans bind
source hashes, environment generations, target state and rollback versions, and
apply rechecks them before target effects. Portable exports retain source bytes
and provenance without machine bindings or transported approval.

The new workspace workflow reuses the managed lifecycle, with target-local
snapshots, capacity checks, conflict detection and durable per-environment
results. Partial or uncertain execution needs journal inspection and explicit
recovery. A shared legacy receipt can migrate several reviewed entries without
completed siblings invalidating pending ones; exact child preconditions and the
original receipt evidence remain enforced. Capacity admission counts shared
snapshot content once, with separate filesystem and per-installation evidence
reserves. Cross-environment operations do not claim global atomicity.

Codex, Cursor CLI and Claude Code use their native Skill roots. Grok Build is an
explicit `grok` host choice with native catalog/file-read verification and its own
configuration conflict checks. Executable identity checks avoid treating an
unrelated `agent` binary as Cursor. Broken native links fail verification, and
source aliases cannot hide plugin ownership or expand capture to a home/filesystem
root. Portable packet extraction rejects case/Unicode ancestor collisions before
staging writes. Enrolled native roots cannot redirect outside their workspace,
and resume checks new discovery conflicts before pending installations advance.
Existing integration and lifecycle v1 interfaces remain available.

See [workspace management](../workspace-management.md) and
[Grok Build](../grok-environments.md) for use, migration and acceptance boundaries.
Filesystem checks, native discovery, actual file reads and useful model operations
are separate results. Native login, folder/hook trust and missing client/runtime
acceptance are never supplied by workspace apply. Cursor CLI authentication and
Grok authenticated model/project-trust checks require their own successful native
evidence; catalog/read evidence alone does not establish those results.

Project Skills remain in their owning repositories. Under the Rule of Three,
shared extraction and a new centralized catalog wait for independent demonstrated
requirements. No background synchronization service is added. Cross-environment
plugin lifecycle, authorization interactions, context and telemetry governance
remain deferred to [issue #23](https://github.com/ERerGB/skills-auditor/issues/23).

Install from the Git tag or attached wheel/source distribution. PyPI publishing
is not configured. Release artifacts, exact-head checks and real target acceptance
are recorded separately in [issue #24](https://github.com/ERerGB/skills-auditor/issues/24).
