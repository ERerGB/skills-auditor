# Skills Auditor 0.9.0

Native vendir delivery can now bind explicitly declared external dependencies into the existing
integration plan and receipt. A missing file, changed bytes, changed permissions or replacement
symlink blocks application or fails verification; drift invalidates version-bound approval.
Older plans without dependencies continue to work. Older Auditor versions reject the new fields.

The main Skill and sync instructions now route cross-filesystem/cloud requests through native
locked delivery, target-local registration and actual Agent acceptance. There is no additional
package manifest, lock format, dependency solver, download service or automatic installation hook.
The managed lifecycle boundary remains enforced; this feature does not silently migrate managed
installations or extend their snapshots with external repository files.

See the [recipe](../vendir-integration.md), [contract](../integration-contract.md) and
[cloud evidence](../../experiments/vendir-potology/CLOUD.md). Prior experiments verified a pinned
Potology task-handoff delivery, explicit dependencies and actual Agent use. Two real Codespaces
proved whole-instance replacement recovery with identical files; in-place full rebuild did not
complete and remains unverified. Those experiments used the pre-release feature tree; release
validation additionally covers integration with the latest managed lifecycle and approval guards.

This release also includes the already merged managed lifecycle and version-bound approval work.
Their contracts and acceptance limits remain in [managed lifecycle](../managed-lifecycle.md).

Install the release from its Git tag or attached wheel. PyPI publishing is not configured.
Runtime setup, private-source authentication, paid resources, hook trust and cloud cleanup remain
explicit environment responsibilities.
