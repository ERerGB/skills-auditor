# Skills Auditor 0.10.1

Fixes [issue #26](https://github.com/ERerGB/skills-auditor/issues/26): installing a
complete Skill package and selecting its nested Skills as flat native entries
could finish every child installation, then incorrectly report a discovery
conflict and leave the workspace transaction partial.

Discovery now recognizes a nested occurrence reached through a selected,
currently owned package when it resolves to the exact selected immutable entry.
Independent native pointers, foreign package aliases, unmanaged selected packages
and different physical entries remain conflicts; equal bytes alone never resolve
an ownership decision.

An affected partial transaction still requires inspection and explicit
`workspace recover --mode resume --approve-plan-id REVIEWED_PLAN_ID`. Recovery
retains the original approved plan, declarations, registry binding and frozen
source bytes. Completed child installations are checked without republishing
their pointers. No automatic retry, new approval or recovery-guard exception is
introduced. See [workspace management](../workspace-management.md).

If a parent package already advanced while its flat nested child is still
pending, the execution boundary also considers that exact saved child's reviewed
next entry. This applies only beneath the current owned parent; final verification
and ordinary planning still require the selected active versions to agree.
For an interrupted publication before metadata commits, discovery requires the
node's recorded in-flight child and its exact approved core transaction, recorded
publication intent and matching observed pointer. This does not adopt an
unmanaged pointer or perform recovery before checking independent native conflicts.

Validation covers a fresh package installation, independent aliases to the same
physical content, and recovery after all 117 children completed, followed by
verification and a zero-change replan. It also covers interrupted parent-first
upgrades and foreign aliases to their pending versions. Native client acceptance and installed
runtime delivery are separate evidence; this fix does not enable plugins or
change their trust or data management.
